## Interaction surfaces

| Surface | Default address | Enabled by default | What it serves |
| --- | --- | --- | --- |
| gRPC | `localhost:9090` | Yes | Application state queries, defined by each module as a `Query` service |
| REST | `tcp://localhost:1317` | No | HTTP bindings of those same query methods, generated by the gRPC gateway |
| CometBFT RPC | `tcp://127.0.0.1:26657` | Yes | Blocks, validators, the mempool, transaction broadcast, and websocket subscriptions |
| CLI | not a network service | n/a | `simd query` and `simd tx`, which call the same methods over gRPC |

gRPC and REST are generated from the same protobuf definitions, so `cosmos.bank.v1beta1.Query/AllBalances` on port 9090 and `GET /cosmos/bank/v1beta1/balances/{address}` on port 1317 reach one set of handlers, not two APIs. A method appears on REST only when it carries an HTTP binding.

CometBFT RPC belongs to the consensus engine underneath the SDK and knows nothing about application modules. See the [CometBFT RPC reference](/cometbft/latest/api-reference/rpc/index).

## Transaction messages

Every module also defines a `Msg` service. Its methods are not endpoints. Each describes a state change the module permits, encoded into a transaction, signed, and broadcast through one of the surfaces above:

```text
cosmos.tx.v1beta1.Service/BroadcastTx     gRPC
POST /cosmos/tx/v1beta1/txs               REST
/broadcast_tx_sync                        CometBFT RPC
```

See [Sending Transactions](/sdk/next/api-reference/transactions).

## Scope

These pages document the services, transaction messages, and REST routes of the standard modules shipped with the Cosmos SDK at the version shown on each page.

A running chain serves only the modules its application registers, may add its own, and may disable routes. For one specific node, reflection is authoritative:

```bash
grpcurl -plaintext localhost:9090 list
```

See [gRPC services](/sdk/next/api-reference/grpc/index) for more reflection recipes.

## Enabling the interfaces

gRPC is on by default. REST is not, and is enabled in `app.toml`:

```toml
[api]
enable = true
address = "tcp://localhost:1317"

# Serves the generated OpenAPI document at /swagger.
swagger = true

[grpc]
enable = true
address = "localhost:9090"
```

CometBFT RPC is configured in `config.toml`:

```toml
[rpc]
laddr = "tcp://127.0.0.1:26657"
```

Both default to localhost. Exposing either publicly requires a deliberate address change and, for browsers, CORS configuration.
