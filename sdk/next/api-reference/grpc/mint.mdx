## Transaction messages

These are not callable endpoints. Each one is encoded into a transaction, signed, and broadcast. See [Sending Transactions](/sdk/next/api-reference/transactions) for how to build, sign, and broadcast one. The handler name is shown for reference and for generated clients, not as an address you can call directly.

The JSON below is transaction JSON, the form the CLI writes and reads and the form `POST /cosmos/tx/v1beta1/encode` accepts. A `cosmos.Dec` field there is a plain decimal string such as `"0.05"`. This holds even where the field's proto type is `bytes`: the base64 form is how such a field reads back over gRPC, not how it is written. The same field passed to the `cosmos.tx.v1beta1.Service/TxEncode` gRPC method instead needs the scaled integer string `"50000000000000000"`, because that path uses a different codec. See [scalar encodings](/sdk/next/api-reference/grpc/index#scalar-encodings).

The signer names the field holding the account whose key must sign the transaction. The Amino name identifies the message under `SIGN_MODE_LEGACY_AMINO_JSON`, the signing mode used by signers that display a transaction for human approval, such as hardware wallets. It is frozen for signature compatibility, so it often does not follow from the message name.
