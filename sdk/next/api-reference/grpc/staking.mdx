A node serves the ones its application registers, on the gRPC server on port 9090, and on the REST gateway on port 1317 where a method carries an HTTP binding. A service defined here is not necessarily one a node answers: `grpcurl -plaintext localhost:9090 list` says what a given node actually serves.

Payloads here are protobuf JSON, where a `cosmos.Dec` is the scaled integer string rather than a decimal. A `string` field may take an enum constant, listed under Types. ## Transaction messages

These are not callable endpoints. Each one is encoded into a transaction, signed, and broadcast. See [Sending Transactions](/sdk/next/api-reference/transactions) for how to build, sign, and broadcast one. The handler name is shown for reference and for generated clients, not as an address you can call directly.

The JSON below is transaction JSON, the form the CLI writes and reads and the form `POST /cosmos/tx/v1beta1/encode` accepts. A `cosmos.Dec` field there is a plain decimal string such as `"0.05"`. This holds even where the field's proto type is `bytes`: the base64 form is how such a field reads back over gRPC, not how it is written. The same field passed to the `cosmos.tx.v1beta1.Service/TxEncode` gRPC method instead needs the scaled integer string `"50000000000000000"`, because that path uses a different codec. See [scalar encodings](/sdk/next/api-reference/grpc/index#scalar-encodings).

The signer names the field holding the account whose key must sign the transaction. The Amino name identifies the message under `SIGN_MODE_LEGACY_AMINO_JSON`, the signing mode used by signers that display a transaction for human approval, such as hardware wallets. It is frozen for signature compatibility, so it often does not follow from the message name.

### cosmos.base.query.v1beta1.PageRequest

PageRequest is to be embedded in gRPC request messages for efficient pagination. Ex:

`message SomeRequest { Foo some_parameter = 1; PageRequest pagination = 2; }`

| Field | Type | Description |
| --- | --- | --- |
| `key` | `bytes` | key is a value returned in PageResponse.next_key to begin querying the next page most efficiently. Only one of offset or key should be set. |
| `offset` | `uint64` | offset is a numeric offset that can be used when key is unavailable. It is less efficient than using key. Only one of offset or key should be set. |
| `limit` | `uint64` | limit is the total number of results to be returned in the result page. If left empty it will default to a value to be set by each app. |
| `count_total` | `bool` | count_total is set to true  to indicate that the result set should include a count of the total number of items available for pagination in UIs. count_total is only respected when offset is used. It is ignored when key is set. |
| `reverse` | `bool` | reverse is set to true if results are to be returned in the descending order. |

### cosmos.staking.v1beta1.Validator

Validator defines a validator, together with the total amount of the Validator's bond shares and their exchange rate to coins. Slashing results in a decrease in the exchange rate, allowing correct calculation of future undelegations without iterating over delegators. When coins are delegated to this validator, the validator is credited with a delegation whose number of bond shares is based on the amount of coins delegated divided by the current exchange rate. Voting power can be calculated as total bonded shares multiplied by exchange rate.
