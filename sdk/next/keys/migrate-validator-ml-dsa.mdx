Migrating a validator to post-quantum signing is an ordinary key rotation with an ML-DSA target key. This guide adds the ML-DSA-specific steps around the standard procedure in [Rotate a validator consensus key, x/staking](/sdk/next/keys/rotate-validator-key). For more information on ML-DSA, see [Post-quantum keys](/sdk/next/keys/post-quantum-keys).

## Prerequisites

- The chain lists `ml_dsa_65` in its consensus params. Check with the commands in [Enable ML-DSA keys on a chain](/sdk/next/keys/enable-ml-dsa-keys). If the type is missing, follow the guide to add it. 
- All prerequisites of the rotation procedure: no rotation in the current unbonding period, and fee funds on the operator account.

<Danger>The new key must be freshly generated. Reusing existing key material on two nodes is a double sign, which tombstones the validator.</Danger>

## 2. Rotate to the new key

Follow [Rotate a validator consensus key, x/staking](/sdk/next/keys/rotate-validator-key) with one difference. The second node runs on the ML-DSA key from step 1, so the rotation message carries the ML-DSA public key. The derivation is unchanged. Run `simd comet show-validator` on the new node's home to print the key in the format the rotation command expects.

On PoA chains, the same migration runs through the PoA rotation message instead, and the cutover timing differs: the node's key is swapped in place after the set switches, rather than running a second node. See [Rotate a validator consensus key, x/poa](/sdk/next/keys/rotate-validator-key-poa).

If the validator's consensus key lives in a remote signer rather than a local file, generate and rotate the key through the signer instead.

## 3. Verify

Check the key type in the validator set:

```shell
curl -s localhost:26657/validators | jq -r '.result.validators[].pub_key.type'
```

A migrated validator reports `cometbft/PubKeyMlDsa65` instead of `tendermint/PubKeyEd25519`. The chain's consensus is post-quantum secure once validators holding at least two thirds of voting power report a post-quantum type. For more information, see [Post-quantum keys](/sdk/next/keys/post-quantum-keys).

## What can go wrong

- The rotation is rejected for an unsupported key type: the chain does not list `ml_dsa_65` yet. See [Enable ML-DSA keys on a chain](/sdk/next/keys/enable-ml-dsa-keys).
- The rotation is rejected with a rotation limit error: a rotation already happened this unbonding period. Wait out the window.
- Anything else follows the standard rotation failure modes. See [Rotate a validator consensus key, x/staking](/sdk/next/keys/rotate-validator-key).
