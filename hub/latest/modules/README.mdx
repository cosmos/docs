This page lists the modules that make up the Cosmos Hub application in gaia v28.3.1, taken from `app/modules.go` in the release, so operators and builders can see which messages and parameters exist on chain. Each module's current parameters come from the query shown next to it (all queries below ran against mainnet on 2026-10-15). Module documentation is kept with the module's source. The Hub pages only cover what the Hub configures differently.

Three modules that older lists mention are not in v28.3.1: the interchain security provider (removed in v28.0.0, as the Hub no longer hosts consumer chains), ICS-29 fee middleware, and the globalfee module (replaced by the fee market). The `gaiad q upgrade module-versions` query still reports `capability` and `crisis` entries from earlier versions. Neither has state or messages any more.

## ibc-go v10.7.0

| Module | What it does on the Hub | Parameters |
| --- | --- | --- |
| [ibc core](/ibc/latest/ibc/overview) | clients, connections, channels, and the IBC v2 client and channel keepers | `gaiad q ibc client params`: `allowed_clients: 07-tendermint, 08-wasm` |
| [07-tendermint](/ibc/latest/ibc/overview) | light client for Cosmos SDK chains | per client |
| [08-wasm](/ibc/latest/light-clients/wasm/overview) | Wasm light clients, used for IBC v2 counterparties such as Ethereum | `gaiad q ibc-wasm checksums` (4 checksums) |
| [transfer](/ibc/latest/apps/transfer/overview) | ICS-20 token transfer, classic and v2 | `gaiad q ibc-transfer params`: send and receive enabled |
| [interchain accounts](/ibc/latest/apps/interchain-accounts/overview) | host (any message allowed) and controller | `gaiad q interchain-accounts host params`: `host_enabled: true`, `allow_messages: ["*"]` |
| [packet forward middleware](/ibc/latest/middleware/packet-forward-middleware/overview) v10.6.0 | multi hop transfers through the Hub | none |
| [rate limiting](/ibc/latest/middleware/rate-limit-middleware/overview) v10.1.0 | per channel, per denom transfer quotas | `gaiad q ratelimit list-rate-limits` (7 limits) |
| [callbacks](/ibc/latest/middleware/callbacks/overview) | contract callbacks on packet lifecycle, classic and v2 | none |

The transfer application is wrapped as transfer, then callbacks, then rate limiting, then packet forward middleware on the classic stack. On the v2 stack it is wrapped as transfer, callbacks, and rate limiting (`app/keepers/keepers.go`).

## Verify

The authoritative list for any release is the module manager in `app/modules.go` at that tag, and the versions the chain has stored:

```bash
gaiad q upgrade module-versions --node https://cosmos-rpc.publicnode.com:443
```

The output lists every module name with its consensus version. A module in the table above with no entry means it has no versioned state (vesting, genutil). An entry with no module above is a leftover from an earlier release (`capability`, `crisis`).
