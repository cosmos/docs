This page is for proposers choosing what to submit and for voters reading a proposal's messages. A Hub proposal on gaia v28.3.1 is a `cosmos.gov.v1.MsgSubmitProposal` carrying zero or more messages that execute if it passes; the type of proposal is just which messages it carries. The process and parameters are on [Governance process](/hub/latest/governance/process).

## The four common types

| Type | Message | On pass |
| --- | --- | --- |
| [Text](/hub/latest/governance/proposal-types/text-prop) | none (empty `messages`) | nothing executes; the vote is the record |
| [Community pool spend](/hub/latest/governance/proposal-types/community-pool-spend) | `/cosmos.distribution.v1beta1.MsgCommunityPoolSpend` | the amount moves from the community pool to the recipient |
| [Parameter change](/hub/latest/governance/proposal-types/param-change) | the target module's `MsgUpdateParams` | the module's parameters are replaced |
| [Software upgrade](/hub/latest/governance/proposal-types/software-upgrade) | `/cosmos.upgrade.v1beta1.MsgSoftwareUpgrade` | an upgrade plan is scheduled at a height |

Every executable message carries an `authority` field that must be the governance module account, `cosmos10d07y265gmmuvt4z0w9aw880jnsr700j6zn9kn`; the module rejects a proposal whose messages name any other authority. Confirm the address from the chain rather than copying it:

```bash
gaiad q auth module-account gov --node https://cosmos-rpc.publicnode.com:443
```

## Other messages the Hub accepts

Any message whose authority is the gov account can go in a proposal. Recent proposals have used:

- `/ibc.core.client.v1.MsgRecoverClient` to replace an expired IBC light client with a working substitute (proposal 1057).
- `/cosmwasm.wasm.v1.MsgUpdateParams` to change who may upload contracts (proposal 1007 made uploads permissionless).
- `/cosmos.upgrade.v1beta1.MsgCancelUpgrade` to clear a scheduled plan before its height.
- `/cosmos.gov.v1.MsgExecLegacyContent` wrapping a legacy `TextProposal`, which older tooling still emits for signaling proposals; it behaves like a text proposal.

Several messages can be combined in one proposal and execute in order; if any fails, none are applied and the proposal is marked failed.

## Choosing a type

Use the executable type whenever the decision can be expressed as a message: a parameter value, an amount to an address, an upgrade height. Voters then know exactly what happens on pass, and nobody has to act afterwards. Use a text proposal when the question is whether to do something that no message can do yet (fund design work, adopt a norm, instruct a team), and say in the summary who is expected to act on the result.

Two mistakes recur:

- A text proposal that asks for a parameter change or a spend. It passes, and nothing happens until someone submits the executable proposal, which then has to pass again.
- An executable proposal whose summary promises more than its messages do. Voters who read the messages (and the ones with most of the stake do) treat the mismatch as grounds for NoWithVeto.

## Expedited proposals

Any type can be marked `"expedited": true` in the proposal JSON. It then needs a 501 ATOM deposit, a 3 day vote and 66.7 percent Yes; if it does not reach that but would pass as a regular proposal it converts to one. Software upgrades for security fixes use it (proposal 1055).

## Rehearse on the testnet

Every message type on this page can be submitted on the Hub testnet (chain-id `provider`) with faucet tokens first. The testnet runs the next gaia release, so a message that the current mainnet accepts but the next version renames shows up there before it costs a mainnet deposit. Endpoints and the faucet are on [Join testnet](/hub/latest/hub-tutorials/join-testnet).

## Verify

Read the messages of any proposal before voting:

```bash
gaiad q gov proposal <id> --output json --node https://cosmos-rpc.publicnode.com:443 | jq '.proposal.messages'
```

The output is the exact message list that will execute. A proposal whose title says one thing and whose messages do another is the case NoWithVeto exists for.
