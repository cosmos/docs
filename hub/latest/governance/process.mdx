This page is for anyone voting on or submitting a Cosmos Hub proposal. It needs no setup; every number on it comes from the chain, with the query that returns it, as of 2026-10-15. How to write and submit a proposal is on [Submitting a proposal](/hub/latest/governance/submitting).

## Parameters

All of these are governance parameters and change through a `cosmos.gov.v1.MsgUpdateParams` proposal (proposal 998 shortened the voting period to 7 days; proposal 1018, which would have put it back to 14, was rejected).

```bash
gaiad q gov params --node https://cosmos-rpc.publicnode.com:443
```

| Parameter | Value | Field in the output |
| --- | --- | --- |
| Minimum deposit | 500 ATOM | `min_deposit: 500000000uatom` |
| Minimum initial deposit | 50 ATOM (10 percent) | `min_initial_deposit_ratio: 0.1` |
| Smallest accepted deposit transaction | 5 ATOM (1 percent) | `min_deposit_ratio: 0.01` |
| Deposit period | 14 days | `max_deposit_period: 336h0m0s` |
| Voting period | 7 days | `voting_period: 168h0m0s` |
| Quorum | 40 percent | `quorum: 0.4` |
| Pass threshold | 50 percent of non-abstain votes | `threshold: 0.5` |
| Veto threshold | 33.4 percent | `veto_threshold: 0.334` |
| Deposit burned on veto | yes | `burn_vote_veto: true` |
| Refund on cancel | 50 percent | `proposal_cancel_ratio: 0.5` |
| Expedited deposit | 501 ATOM | `expedited_min_deposit: 501000000uatom` |
| Expedited voting period | 3 days | `expedited_voting_period: 72h0m0s` |
| Expedited threshold | 66.7 percent | `expedited_threshold: 0.667` |

The Hub adds one rule outside these parameters: a vote is accepted only from an address with at least 1 ATOM staked (1,000,000 uatom summed over its first 100 delegations). This is enforced in gaia's ante handler, not in the SDK gov module.

## 1. Deposit period

A proposal exists on chain from the moment it is submitted with at least 50 ATOM, and enters voting as soon as the total deposit reaches 500 ATOM. Anyone can add to the deposit, in increments of at least 5 ATOM, for up to 14 days; after that the proposal is removed and the deposits are refunded.

```bash
gaiad q gov proposals --proposal-status deposit-period --node https://cosmos-rpc.publicnode.com:443
gaiad q gov deposits <id> --node https://cosmos-rpc.publicnode.com:443
```

Deposits are refunded after the vote in every case except a veto. With `burn_vote_veto: true`, a proposal that ends with 33.4 percent or more NoWithVeto loses the whole deposit; proposal 1056 is a recent example. Deposits are not burned for failing quorum or for a plain No majority. A proposer can cancel a proposal before the voting period ends with `gaiad tx gov cancel-proposal <id>`, and half of the deposit is burned.

## 2. Voting period

Voting lasts 7 days from the moment the deposit is filled (3 days for an expedited proposal). Any address with at least 1 ATOM staked can vote once and can change the vote until the period ends; the last vote counts.

```bash
gaiad q gov proposals --proposal-status voting-period --node https://cosmos-rpc.publicnode.com:443
gaiad q gov proposal <id> --node https://cosmos-rpc.publicnode.com:443
gaiad q gov tally <id> --node https://cosmos-rpc.publicnode.com:443
```

`proposal` prints `voting_end_time`, `total_deposit` and `title`; `tally` prints the running `yes_count`, `no_count`, `abstain_count` and `no_with_veto_count` in uatom.

The four options:

- Yes: approve the proposal as written.
- No: reject it as written.
- Abstain: count toward quorum without taking a side. Abstain votes are excluded when the threshold is computed.
- NoWithVeto: reject it and burn the deposit. By community agreement in proposal 75, this is for proposals that are spam, that disproportionately harm a minority, or that break rules the Hub has adopted through governance. Voting NoWithVeto costs the voter nothing.

A vote can be split across options with `weighted-vote` (for example `yes=0.6,no=0.4`), which custodians use to pass through their clients' choices. Commands are on the [Delegator CLI guide](/hub/latest/delegators/delegator-guide-cli#vote).

## 3. Tally

A proposal passes when all four hold at the end of the voting period:

1. The deposit reached 500 ATOM within 14 days (otherwise there is no vote).
2. Quorum: at least 40 percent of all bonded ATOM voted (Yes, No, Abstain and NoWithVeto all count).
3. Threshold: more than 50 percent of the votes, excluding Abstain, are Yes.
4. Veto: fewer than 33.4 percent of all votes are NoWithVeto. A veto at or above that fails the proposal even with a Yes majority, so a third of the voting stake can block anything.

An expedited proposal uses the 66.7 percent threshold and the 3 day period; if it fails to reach that threshold but would have passed as a regular proposal, it converts to a regular proposal and the voting period continues to the regular length.

Voting power is bonded ATOM at the end of the voting period. Liquid ATOM does not vote. A delegator who does not vote inherits the vote of each validator they delegate to, in proportion; a delegator who votes overrides that for their own stake. Votes from validators outside the active set when the period ends, including jailed or tombstoned validators, carry no weight, and neither do the inherited votes of their delegators.

```bash
gaiad q gov proposals --proposal-status passed --page-reverse --page-limit 5 --node https://cosmos-rpc.publicnode.com:443
```

Each proposal prints `final_tally_result` with the four counts. Proposal 1055 (the v28.2.0 upgrade) was expedited and passed with 146,696,672 ATOM Yes against under 3,000 ATOM in other votes.

## What happens after a pass

Messages in a passed proposal execute at the end of the voting period, in the same block as the tally: a software upgrade plan is scheduled, parameters change, community pool funds move. A text proposal with no messages executes nothing and stands as a record. If a message fails at execution (an upgrade height already in the past, for example), the proposal status becomes `PROPOSAL_STATUS_FAILED` and nothing is applied.

## Verify

Confirm your own vote was recorded while the period is open:

```bash
gaiad q gov vote <id> cosmos1... --node https://cosmos-rpc.publicnode.com:443
```

The output lists `options` with the option and weight; an error `not found` means the vote did not land (wrong proposal id, or the address had under 1 ATOM staked and the transaction failed, which `gaiad q tx <hash>` shows with a non-zero code).
