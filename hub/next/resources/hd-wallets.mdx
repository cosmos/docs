This page is for anyone creating or recovering a Cosmos Hub wallet key with `gaiad keys` ([gaiad reference](/hub/next/hub-tutorials/gaiad)), Keplr or a Ledger. It explains why one phrase yields many addresses and which flags pick them, so a recovered wallet lands on the expected address.

## Terms

Five terms cover everything on this page, and the mnemonic is the one that matters most because it reproduces all the others.

- Mnemonic (seed phrase): 24 words from which every key in the wallet is derived. It is the wallet; everything else can be recomputed from it.
- Private key: the secret that signs transactions for one account. Derived from the mnemonic and a path.
- Public key: computed from the private key with a one way function. The chain stores it after the account's first signed transaction.
- Address: a hash of the public key, shown with a readable prefix (`cosmos1...`). The same key also has `cosmosvaloper1...` and `cosmosvalcons1...` encodings, which are prefixes, not separate keys.
- Account (in HD terms): one private key, public key and address derived from the mnemonic at one path.

Each step is one way: the mnemonic produces the private key, the private key the public key, the public key the address, and none can be reversed.

```text
   Account 0            Account 1            Account 2
   Address 0            Address 1            Address 2
       ^                    ^                    ^
   Public key 0         Public key 1         Public key 2
       ^                    ^                    ^
   Private key 0        Private key 1        Private key 2
       ^                    ^                    ^
       +--------------------+--------------------+
                            |
                     Mnemonic (seed)
```

## The derivation path

Cosmos wallets follow BIP-32 and BIP-44. The path `gaiad` uses by default is:

```text
m/44'/118'/0'/0/0
```

`44'` marks BIP-44, `118'` is the coin type registered for Cosmos, the third number is the account, the fourth is the change field (always 0 for Cosmos) and the last is the address index. Changing the account or the index gives a different, unrelated address from the same mnemonic; the same path always gives the same address, which is what makes recovery possible.

```bash
gaiad keys add mykey
gaiad keys add mykey-1 --index 1
gaiad keys add mykey-acct1 --account 1
gaiad keys add mykey-custom --hd-path "m/44'/118'/0'/0/5"
```

`--account` and `--index` set the third and fifth path elements; `--hd-path` sets the whole path and overrides both; `--coin-type` (default 118) changes the second. `--index 1` and `--hd-path "m/44'/118'/0'/0/1"` produce the same address. Keplr and Ledger use the same path, so a key created in one tool recovers in another as long as the path matches. Add `--dry-run` to see the address a path would produce without saving the key.

## Recovering a wallet

```bash
gaiad keys add mykey --recover
```

`--recover` prompts for the mnemonic and derives the key at the default path. If the resulting address is not the one expected, the original key was created at another index or account; retry with `--index` or `--account` until the address matches, or check the expected address in the explorer first. Recovery writes the private key into the keyring selected by `--keyring-backend` ([Keyring](/sdk/latest/node/keyring)), so recover on a trusted machine only.

<Warning>
Anyone with the 24 words controls every account derived from them, on every chain that uses the same coin type. Keep offline copies in more than one safe place, never type the words into a web page, and never store them next to the keyring they recover.
</Warning>

## What the mnemonic does not cover

A validator's consensus key (`priv_validator_key.json`) and node key (`node_key.json`) are ed25519 keys generated by `gaiad init`, not derived from a mnemonic; back up those files separately ([Validator setup](/hub/next/validators/validator-setup)). Multisig entries in the keyring are combinations of public keys and are rebuilt from the member keys, not from a phrase. A Ledger key's mnemonic lives on the device ([Ledger](/hub/next/resources/ledger)).

## Verify

```bash
gaiad keys add check --dry-run --recover --index 0
gaiad keys add check --dry-run --recover --index 1
```

Both prompts accept the same mnemonic and print different addresses; repeating either command prints the same address again, which confirms the derivation is deterministic. Nothing is saved with `--dry-run`.
