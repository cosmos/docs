This page is for an operator with a node that is fully synced to cosmoshub-4 and running as a service ([Join mainnet](/hub/next/hub-tutorials/join-mainnet), [Run gaiad as a service](/hub/next/node/service)). At the end you have a validator registered on chain and know every operator-key transaction you will send over its life.

All transactions below are signed by the operator key and cost a fee in `uatom`. Add `--chain-id cosmoshub-4 --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom` to each; 0.005 uatom per gas was the fee market floor on 2026-10-15 (`gaiad query feemarket gas-prices`). Test every command on the [testnet](/hub/next/hub-tutorials/join-testnet) first with the testnet chain-id.

## Prerequisites

- An operator key in the keyring. Create one with `gaiad keys add <name>`, or `gaiad keys add <name> --ledger` to keep it on a [Ledger](/hub/next/resources/ledger). Use the `os` or `file` keyring backend on a server, never `test`. See [Keyring](/sdk/latest/node/keyring).
- ATOM on the operator address for the self-delegation plus fees. `gaiad keys show <name> -a` prints the `cosmos` address; `gaiad keys show <name> --bech val -a` prints the `cosmosvaloper` address you will query later.
- The consensus public key. On the node host, `gaiad comet show-validator` prints it from `config/priv_validator_key.json`. If you already moved the key to a [remote signer](/hub/next/validators/remote-signing), take the key from `curl -s localhost:26657/status | jq .result.validator_info.pub_key` instead; `show-validator` always reads the local file.
- The node reports `"catching_up": false` in `curl -s localhost:26657/status | jq .result.sync_info`. A validator created while behind the head misses blocks immediately.

## Write validator.json

On gaia v28.3.1, `create-validator` takes a JSON file, not flags. `gaiad tx staking create-validator --help` prints the schema.

```json
{
  "pubkey": {"@type":"/cosmos.crypto.ed25519.PubKey","key":"U1ONwh10OTBOB+PcDhpQLupEyx2gJoYvDkZ6f7fYbIE="},
  "amount": "1000000uatom",
  "moniker": "docs-validator",
  "identity": "",
  "website": "https://example.com",
  "security": "security@example.com",
  "details": "",
  "commission-rate": "0.10",
  "commission-max-rate": "0.20",
  "commission-max-change-rate": "0.01",
  "min-self-delegation": "1"
}
```

Field by field:

- `pubkey`: the exact output of `gaiad comet show-validator` (or the `/status` key, converted to the same `@type` form). A wrong key creates a validator that can never sign.
- `amount`: the initial self-delegation. 1,000,000 uatom is 1 ATOM. The active set cutoff is far higher; see [Live constraints](/hub/next/validators/overview#live-constraints).
- `identity`: a 16-character Keybase PGP fingerprint, used by explorers for your logo. Optional.
- `commission-rate`: at least 0.05, the chain minimum. The binary does not check this; a lower value is rejected when the transaction executes.
- `commission-max-rate` and `commission-max-change-rate`: fixed forever at creation. You can never raise commission above the max, or move it by more than the max change in one day.
- `min-self-delegation`: whole uatom, at least 1. Can only be increased later. Dropping your self-delegation below it jails the validator.

## Create the validator

```bash
gaiad tx staking create-validator validator.json \
  --from <operator-key-name> \
  --chain-id cosmoshub-4 \
  --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom
```

This sends `MsgCreateValidator`, bonds `amount` from the operator address, and registers the description and commission. Use `--generate-only` first to inspect the unsigned transaction without broadcasting it. The response code must be `0`; a non-zero code prints the reason (insufficient funds, commission below minimum, duplicate consensus key).

## Verify

```bash
gaiad query staking validator $(gaiad keys show <operator-key-name> --bech val -a)
```

A new validator with less stake than the 180th seat shows `status: BOND_STATUS_UNBONDED` and `jailed: false`. It becomes `BOND_STATUS_BONDED` at the end of the block in which its voting power enters the top 180.

```bash
curl -s localhost:26657/status | jq '.result.validator_info'
```

`voting_power` is `0` until the validator is bonded, then equals bonded ATOM. `pub_key` must match the key in `validator.json`.

```bash
gaiad query slashing signing-info $(gaiad comet show-validator)
```

Once bonded, `index_offset` increases every block and `missed_blocks_counter` stays flat (with `--output json` the field is omitted while it is zero, as are `tombstoned` and `jailed_until` when unset). Explorers such as [Mintscan](https://www.mintscan.io/cosmos/validators) list the validator within a few minutes.

## Edit the validator

`edit-validator` is flag based. Only the flags you pass change; everything else keeps its value.

```bash
gaiad tx staking edit-validator \
  --new-moniker "<name>" \
  --website "https://example.com" \
  --security-contact "security@example.com" \
  --identity "<keybase-fingerprint>" \
  --details "<one line>" \
  --from <operator-key-name> \
  --chain-id cosmoshub-4 --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom
```

Two flags carry rules enforced by the chain:

- `--commission-rate`: at most one change per 24 hours, never above your `commission-max-rate`, never moving more than `commission-max-change-rate` at once, never below the chain minimum 0.05. A second change inside 24 hours fails with `commission cannot be changed more than once in 24h`.
- `--min-self-delegation`: can only go up, and not above your current self-delegation.

Confirm with the same `gaiad query staking validator` call; the `description` and `commission` fields update in the next block.

## Unjail

If the validator is jailed for downtime, fix the cause first (signer down, node stopped, missed upgrade), confirm the node is at the chain head and signing is possible, then:

```bash
gaiad tx slashing unjail --from <operator-key-name> \
  --chain-id cosmoshub-4 --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom
```

The chain rejects the transaction while `jailed_until` (10 minutes after the jailing) has not passed, if self-delegation is below `min-self-delegation`, or if the validator was tombstoned for a double sign. A tombstoned validator cannot be unjailed by anyone.

`gaiad query staking validator <cosmosvaloper>` shows `jailed: false` and the validator re-enters the set at the next block if its power qualifies.

## Rewards and withdraw address

Commission accrues in the distribution module until you withdraw it.

```bash
gaiad tx distribution withdraw-rewards <cosmosvaloper> --commission \
  --from <operator-key-name> \
  --chain-id cosmoshub-4 --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom
```

This sends `MsgWithdrawDelegatorReward` for the self-delegation and `MsgWithdrawValidatorCommission` for commission. To pay rewards to a different account (a cold wallet, for example):

```bash
gaiad tx distribution set-withdraw-addr <cosmos-address> --from <operator-key-name> \
  --chain-id cosmoshub-4 --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom
```

`gaiad query distribution commission <cosmosvaloper>` shows the unclaimed commission.

## Liquid staking

By default anyone can tokenize delegations to your validator inside the chain caps (25 percent global, 100 percent per validator; see [Liquid staking](/hub/next/modules/liquid)). To refuse tokenized shares:

```bash
gaiad tx liquid disable-tokenize-shares --from <operator-key-name> \
  --chain-id cosmoshub-4 --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom
```

Re-enabling takes `enable-tokenize-shares` plus the unbonding period before it applies. There is no validator bond requirement on the Hub.

## Stop at a height

For maintenance you cannot script otherwise, make the node stop itself at a block:

```bash
gaiad config set app halt-height <height>
```

The TOML key is `halt-height` in `app.toml`; `gaiad start --halt-height <height>` does the same for one run. Reset it to `0` before the restart or the node stops again. Remember the downtime window: about 15 hours of missed blocks jails you (see [Validator overview](/hub/next/validators/overview#live-constraints)).

## Leave the set cleanly

<Warning>
There is no "unbond validator" transaction on gaia v28.3.1. Stopping the node and walking away jails you for downtime after about 15 hours and slashes 0.01 percent of all stake delegated to you, including your delegators'. Exit by reducing self-delegation instead.
</Warning>

Undelegating your own stake below `min-self-delegation` jails the validator at once, without a slash, and removes it from the set at the end of the block:

```bash
gaiad tx staking unbond <cosmosvaloper> <amount>uatom --from <operator-key-name> \
  --chain-id cosmoshub-4 --gas auto --gas-adjustment 1.5 --gas-prices 0.005uatom
```

Keep the node and signer running until `gaiad query staking validator <cosmosvaloper>` shows `jailed: true` and `status` other than `BOND_STATUS_BONDED`. Tell your delegators ahead of time so they can redelegate; their stake, and your remaining self-delegation, unbonds over 21 days and stays slashable for evidence from before the exit. The `cosmosvaloper` address is permanent, so a later return means `unjail` on the same validator, not a new one.

## Common problems

- `voting_power: 0` in `/status` long after creation: the validator is below the 180th seat, or the `pubkey` in `validator.json` is not the key the node signs with. Compare `gaiad query staking validator` `consensus_pubkey` with `/status` `validator_info.pub_key`.
- `create-validator` fails with a commission error: `commission-rate` below 0.05 or above `commission-max-rate`.
- `jailed: true` right after a commission change: unrelated; check `gaiad query slashing signing-info` for `jailed_until` and the node logs for the gap.
- Too many open files or peer drops under load: raise the service file descriptor limit; see [Run gaiad as a service](/hub/next/node/service).
