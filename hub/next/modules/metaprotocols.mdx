The `x/metaprotocols` module adds support for encoding and decoding additional fields attached to transactions. It is for builders of protocols that write data into Hub transactions (inscriptions, indexers) and for operators who see `/gaia.metaprotocols.ExtensionData` in blocks and want to know what it is. Source: [x/metaprotocols README](https://github.com/cosmos/gaia/blob/v28.3.1/x/metaprotocols/README.md).

The `extension_options` and `non_critical_extension_options` fields are optional. They can be used to attach data to valid transactions. The blockchain validates the fields but does not use them in any way. The fields pass validation if they are provided as empty lists (`[ ]`) or as a list of `ExtensionData` types.

The application does not use the attached data. It does ensure that the correct type is provided and that the data can be unmarshalled. The attached data becomes part of a block.

<Tip>
Use only `/gaia.metaprotocols.ExtensionData` in `extension_options` and `non_critical_extension_options`. A transaction that populates either field with another type is invalid and is rejected.
</Tip>

The following is a correctly formed `non_critical_extension_options` entry. The `@type` must be exactly `/gaia.metaprotocols.ExtensionData`:

```json
{
  "@type": "/gaia.metaprotocols.ExtensionData",
  "protocol_id": "some-protocol",
  "protocol_version": "1",
  "data": "<base64 encoded bytes>"
}
```

The following is a `bank.MsgSend` transaction with a correctly populated `non_critical_extension_options` field:

```json expandable
{
  "body": {
    "messages": [
      {
        "@type": "/cosmos.bank.v1beta1.MsgSend",
        "from_address": "cosmos1ehpqg9sj09037uhe56sqktk30asn47asthyr22",
        "to_address": "cosmos1ehpqg9sj09037uhe56sqktk30asn47asthyr22",
        "amount": [
          {
            "denom": "uatom",
            "amount": "100"
          }
        ]
      }
    ],
    "memo": "memo_smaller_than_512_bytes",
    "timeout_height": "0",
    "extension_options": [],
    "non_critical_extension_options": [
      {
        "@type": "/gaia.metaprotocols.ExtensionData",
        "protocol_id": "some-protocol",
        "protocol_version": "1",
        "data": "<base64 encoded bytes>"
      }
    ]
  },
  "auth_info": {
    "signer_infos": [],
    "fee": {
      "amount": [],
      "gas_limit": "200000",
      "payer": "",
      "granter": ""
    }
  },
  "signatures": []
}
```

## Verify

Decode any transaction that carries extension data and check that the type is the one the Hub accepts:

```bash
gaiad q tx <txhash> --output json | jq '.tx.body.non_critical_extension_options[]."@type"'
```

The output is `/gaia.metaprotocols.ExtensionData` for every entry. A transaction with any other type in either extension field is rejected before it reaches a block.
