You have a node that starts cleanly in the foreground from [Join mainnet](/hub/next/hub-tutorials/join-mainnet). At the end the node runs as a dedicated user under systemd, restarts on failure, survives reboots, and logs to the journal. Pick the Cosmovisor unit if the node will follow Hub upgrades, which is most mainnet nodes. The plain unit is for containers, test machines, and nodes you upgrade by hand.

## Create a service user

```bash
sudo useradd --system --create-home --home-dir /var/lib/gaia --shell /usr/sbin/nologin gaia
sudo install -d -o gaia -g gaia -m 0750 /var/lib/gaia/.gaia
```

A system user with no login shell owns the node home and nothing else. If you initialized the node as your own user, move `~/.gaia` to `/var/lib/gaia/.gaia`. Then run `chown -R gaia:gaia` on it. The two key files deserve stricter modes than the rest:

```bash
sudo chmod 0600 /var/lib/gaia/.gaia/config/priv_validator_key.json /var/lib/gaia/.gaia/config/node_key.json
```

The `priv_validator_key.json` file is the consensus key. It cannot be rotated on the Hub today, so the service user is the only account that should be able to read it. A validator should move signing off this machine entirely with [remote signing](/hub/next/validators/remote-signing). The `node_key.json` file holds no on-chain state and can be regenerated if lost. However, a stable node id keeps your peers' persistent peer lists valid.

## Plain gaiad unit

```bash
sudo tee /etc/systemd/system/gaiad.service > /dev/null <<'EOT'
[Unit]
Description=Cosmos Hub node (gaiad)
After=network-online.target
Wants=network-online.target

[Service]
User=gaia
Group=gaia
ExecStart=/usr/local/bin/gaiad start --home /var/lib/gaia/.gaia
Restart=on-failure
RestartSec=10
LimitNOFILE=50000
KillSignal=SIGINT
TimeoutStopSec=120

[Install]
WantedBy=multi-user.target
EOT
```

The `ExecStart` line uses absolute paths because systemd has no shell `PATH`. The value `LimitNOFILE=50000` is what the gaia upgrade guide uses. The old 4096 default runs out under peer load, and the node crashes with `too many open files`. The `KillSignal=SIGINT` setting with a two minute stop timeout lets gaiad flush its stores instead of being killed mid write. The `Restart=on-failure` setting brings the node back after a crash but not after a clean stop, so a stop you asked for stays stopped.

## Cosmovisor unit

Cosmovisor is the Cosmos SDK process manager that watches for an upgrade height and swaps the `gaiad` binary. Install it and lay out the directories once. [Upgrade a node](/hub/next/hub-tutorials/upgrade-node) covers what happens at each upgrade.

```bash
go install cosmossdk.io/tools/cosmovisor/cmd/cosmovisor@v1.7.3
sudo install -m 0755 "$(go env GOPATH)/bin/cosmovisor" /usr/local/bin/cosmovisor
sudo -u gaia env DAEMON_NAME=gaiad DAEMON_HOME=/var/lib/gaia/.gaia cosmovisor init /usr/local/bin/gaiad
```

The `go install` step needs Go 1.25 on the machine. Release archives for linux-amd64 and linux-arm64 are on the [cosmovisor v1.7.3 release](https://github.com/cosmos/cosmos-sdk/releases/tag/cosmovisor%2Fv1.7.3) if you would rather not build it. The `cosmovisor init` command copies the current binary to `cosmovisor/genesis/bin/gaiad`, points the `cosmovisor/current` symlink at `genesis`, and writes `cosmovisor/config.toml`. Cosmovisor v1.7.3 prints `v1.7.3` for `cosmovisor version`. It errors if `DAEMON_NAME` and `DAEMON_HOME` are unset, which is why the environment is passed inline.

```bash
sudo tee /etc/systemd/system/cosmovisor.service > /dev/null <<'EOT'
[Unit]
Description=Cosmos Hub node (gaiad under cosmovisor)
After=network-online.target
Wants=network-online.target

[Service]
User=gaia
Group=gaia
ExecStart=/usr/local/bin/cosmovisor run start --home /var/lib/gaia/.gaia
Restart=no
LimitNOFILE=50000
KillSignal=SIGINT
TimeoutStopSec=120
Environment="DAEMON_NAME=gaiad"
Environment="DAEMON_HOME=/var/lib/gaia/.gaia"
Environment="DAEMON_ALLOW_DOWNLOAD_BINARIES=false"
Environment="DAEMON_RESTART_AFTER_UPGRADE=true"
Environment="DAEMON_LOG_BUFFER_SIZE=512"
Environment="UNSAFE_SKIP_BACKUP=true"

[Install]
WantedBy=multi-user.target
EOT
```

The command is `cosmovisor run start`. The `cosmovisor start` form from older guides no longer exists. The `Restart=no` setting is deliberate and comes from the gaia upgrade guide. Cosmovisor itself restarts gaiad after a successful upgrade. A systemd restart loop on a failed upgrade would keep relaunching a binary that cannot apply the block. Setting `DAEMON_ALLOW_DOWNLOAD_BINARIES=false` means you place every upgrade binary yourself and verify it. Auto download trusts whatever URL the proposal named. Setting `UNSAFE_SKIP_BACKUP=true` skips the pre upgrade copy of `data/`, which on a Hub node would take longer than the upgrade and double the disk. Take your own backup before upgrade day instead.

Confirm the environment Cosmovisor sees:

```bash
sudo -u gaia env DAEMON_NAME=gaiad DAEMON_HOME=/var/lib/gaia/.gaia cosmovisor config
```

This prints every `DAEMON_*` value and the derived paths, including the monitored file `data/upgrade-info.json`.

## Enable and start

Use one of the two units, never both, since they start the same node on the same ports.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now cosmovisor
sudo systemctl status cosmovisor --no-pager
```

The `daemon-reload` command makes systemd read the new unit. The `enable --now` command starts it and arranges a start at boot. The `status` command shows `active (running)` with the last log lines. Substitute `gaiad` for the plain unit.

## Logs

```bash
journalctl -u cosmovisor -f -o cat
journalctl -u cosmovisor --since "1 hour ago" | grep -E 'ERR|panic' | tail
```

The first follows the live log without timestamps added by the journal (gaiad prints its own). The second is the first thing to run when a node looks unhealthy. Set a journal size cap in `/etc/systemd/journald.conf` (`SystemMaxUse=2G`) so a chatty node cannot fill the root disk.

## Stop and restart safely

```bash
sudo systemctl stop cosmovisor
sudo systemctl start cosmovisor
```

A stop sends SIGINT and waits up to `TimeoutStopSec`. Let it finish. A restart on a validator costs the blocks missed while the node reconnects to peers, typically under a minute. That is why configuration changes get batched into one restart.

## Verify

```bash
systemctl is-active cosmovisor
systemctl is-enabled cosmovisor
curl -s localhost:26657/status | jq '{height: .result.sync_info.latest_block_height, catching_up: .result.sync_info.catching_up}'
ls -l /var/lib/gaia/.gaia/cosmovisor/current
```

Expect `active`, `enabled`, a climbing height, and a `current` symlink pointing at `genesis` until the first upgrade moves it to `upgrades/<name>`.
