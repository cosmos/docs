## The validator onboarding path

Follow these pages in order if you are new. Each page ends with a Verify section and a link to the next step.

1. [What is gaia](/hub/next/getting-started/what-is-gaia): the software, the chain, and what has changed in it.
2. [Versions](/hub/next/start/versions): the exact stack the Hub runs today and which upstream docs apply.
3. [System requirements](/hub/next/getting-started/system-requirements): sizing by node type.
4. [Install gaiad](/hub/next/getting-started/installation): signed binaries, the container image, or a source build.
5. [Join mainnet](/hub/next/hub-tutorials/join-mainnet): initialize, configure, sync, and start a full node.
6. [Run gaiad as a service](/hub/next/node/service): systemd units for gaiad and Cosmovisor.
7. [Validator setup](/hub/next/validators/validator-setup): create the validator and manage its keys.
8. [Upgrade a node](/hub/next/hub-tutorials/upgrade-node): the Cosmovisor runbook for Hub upgrades.

Practice on the [public testnet](/hub/next/hub-tutorials/join-testnet) first. It runs the next gaia release before mainnet does.

## What the Hub runs today

The Hub currently runs gaia v28.3.1 on Cosmos SDK v0.53.4 and CometBFT v0.38.23, with ibc-go v10.7.0 and wasmd v0.60.9. The full list, the testnet version, and the routing to the matching Cosmos SDK, CometBFT, and IBC pages are on the [Versions](/hub/next/start/versions) page. Check the live version from any public RPC before you build:

```bash
curl -s https://cosmos-rpc.polkachu.com/abci_info | jq -r '.result.response.version'
```

## How these pages are verified

Every command page carries a box like the one at the top of this page. It names the gaia version the commands were run on and the date. Commands were run by agent testing on a local devnet or against the release binary, then reviewed. Values that change over time (gas prices, peers, trust heights, snapshot providers) carry the date they were checked. If a page says "checked 2026-10-15" and today is much later, confirm the value from the query shown next to it before relying on it.

Operators and ATOM holders who find a wrong command or a stale value should open an issue or pull request at [cosmos/docs](https://github.com/cosmos/docs).
